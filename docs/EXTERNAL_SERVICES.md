# External Services Configuration & Verification Guide

This document defines the configuration, verification procedures, fallback mechanisms, and security protocols for external third-party integrations in the **Smart Civic Issue Resolution Agent**:
1. **Google Gemini Generative AI** (`GEMINI_API_KEY`)
2. **Cloudinary Media Storage** (`CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`)

> [!IMPORTANT]
> **Test Suite Notice**: Automated unit/integration test suites use deterministic fallbacks and mocked adapters to guarantee reproducible CI/CD execution without network dependencies.
> **Live Verification Notice**: Manual end-to-end verification against real external infrastructure requires valid, active credentials configured in a local, uncommitted `.env` file.

---

## 1. Required Environment Variables

The application relies on the following exact environment variable names in `server/.env`:

| Service | Variable Name | Purpose | Example / Format |
|---|---|---|---|
| **Gemini AI** | `GEMINI_API_KEY` | Authentication key for Google Generative AI REST API | `AIzaSy...` (39 chars) |
| **Gemini AI** | `GEMINI_MODEL` | *(Optional)* Target Gemini model name (default: `gemini-1.5-flash`) | `gemini-1.5-flash` |
| **Cloudinary** | `CLOUDINARY_CLOUD_NAME` | Cloudinary account cloud name | e.g. `your_cloud_name` |
| **Cloudinary** | `CLOUDINARY_API_KEY` | Cloudinary account API key identifier | e.g. `641143458285714` |
| **Cloudinary** | `CLOUDINARY_API_SECRET` | Cloudinary API secret signature key | e.g. `NASAD5...` |

## 2. Gemini AI Setup

1. **Obtain API Key**:
   - Create or access a project in [Google AI Studio](https://aistudio.google.com/).
   - Generate an API key with access to Gemini 1.5 Flash models.
2. **Configure Local Environment**:
   - In `server/.env`, set:
     ```env
     GEMINI_API_KEY=your_actual_gemini_api_key_here
     GEMINI_MODEL=gemini-1.5-flash
     ```
3. **Execution Pipeline**:
   - The Gemini client is implemented in `server/src/services/ai/gemini.client.js`.
   - Uses Node's native `fetch` to communicate directly with `https://generativelanguage.googleapis.com/v1beta/models`.
   - Orchestrated in `agentOrchestrator.service.js` across classification, evidence analysis, severity assessment, department mapping, and complaint formatting.

---

## 3. Cloudinary Setup

1. **Obtain Credentials**:
   - Create an account on [Cloudinary](https://cloudinary.com/).
   - Navigate to the Dashboard / API Keys console to locate:
     - Cloud Name
     - API Key
     - API Secret
2. **Configure Local Environment**:
   - In `server/.env`, set:
     ```env
     CLOUDINARY_CLOUD_NAME=your_cloud_name
     CLOUDINARY_API_KEY=your_api_key
     CLOUDINARY_API_SECRET=your_api_secret
     ```
3. **Execution Pipeline**:
   - Storage service is abstracted in `server/src/services/storage.service.js`.
   - During complaint intake (`POST /api/v1/complaints/analyze`), Multer receives the image and writes to `uploads/`.
   - `storageService.uploadImage(filePath)` uploads the file to `smart-civic/complaints` folder in Cloudinary.
   - Temporary local upload files are cleaned up from disk immediately after upload completes or upon error.

## 4. How to Verify Gemini is Live

### Manual Verification Procedure:
1. Verify `geminiClient.isConfigured()` returns `true` (non-empty key that differs from placeholder `'your_gemini_api_key'`).
2. Run a complaint analysis request:
   ```http
   POST /api/v1/complaints/analyze
   Content-Type: application/json
   Cookie: jwt=<citizen_jwt>

   {
     "description": "Massive deep pothole on MG Road near Metro Station causing severe road hazard",
     "location": { "latitude": 12.9716, "longitude": 77.5946, "address": "MG Road" }
   }
   ```
3. **Distinguishing LIVE vs FALLBACK**:
   - **Real Gemini**:
     - The response `aiAnalysis` displays contextual reasoning dynamically generated by the Gemini model.
     - Confidence scores vary based on model probability (e.g., `0.94`).
     - Network inspection confirms outbound HTTP call to `generativelanguage.googleapis.com`.
   - **Deterministic Fallback**:
     - Produces pre-configured rule-based confidence (e.g., fixed `0.92` for pothole, `0.50` for other).
     - Rationale strings match fixed template phrases defined in `classifyIssue.service.js`.

---

## 5. How to Verify Cloudinary is Live

### Manual Verification Procedure:
1. Ensure `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, and `CLOUDINARY_API_SECRET` are present in `server/.env`.
2. Submit a complaint intake with a real image file attached via `multipart/form-data`:
   ```bash
   curl -X POST http://localhost:5000/api/v1/complaints/analyze \
     -b "jwt=<citizen_jwt>" \
     -F "description=Severe pothole on roadway" \
     -F 'location={"latitude": 12.9716, "longitude": 77.5946, "address": "MG Road"}' \
     -F "image=@/path/to/test_image.png"
   ```
3. **Distinguishing LIVE vs FALLBACK**:
   - **Real Cloudinary**:
     - Response evidence URL matches the configured cloud name:
       `https://res.cloudinary.com/<CLOUDINARY_CLOUD_NAME>/image/upload/v.../smart-civic/complaints/<public_id>.png`
     - The image is viewable in a browser and appears in your Cloudinary Media Library dashboard.
   - **Deterministic Fallback**:
     - Returns placeholder demo URL:
       `https://res.cloudinary.com/demo/image/upload/sample.jpg` with `publicId: "sample"`.

## 6. Fallback Behavior

Both Gemini and Cloudinary feature robust deterministic fallbacks:
- **Offline / Isolated Testing**: Allows developers to run tests and local intake flows without network connectivity or third-party quota consumption.
- **Graceful Degradation**: If Google Generative AI or Cloudinary encounters an outage or rate limit (HTTP 429/500), the backend falls back to local heuristic classifiers and deterministic responses instead of crashing citizen intake.
- **Contract Adherence**: Fallback responses produce the identical 7-key output schema expected by the application.

---

## 7. Development vs Production Notes

- **Development**:
  - Developers can work offline using built-in deterministic fallbacks when API keys are omitted.
  - Temporary files are written to `server/uploads/` and deleted immediately after processing.
- **Production**:
  - Live `GEMINI_API_KEY` and Cloudinary credentials must be set in secure environment variables (e.g., cloud secrets manager).
  - All complaint media is persisted to Cloudinary CDN and stored as HTTPS URLs in MongoDB.
  - Fallback triggers should be monitored via operational logs and error tracking.

---

## 8. Security Rules

1. **Zero Secret Commits**:
   - `.env` files are strictly excluded via `.gitignore` and must NEVER be staged or committed to Git.
   - Run `git status` before every commit to ensure no untracked `.env` files are included.
2. **No Credential Logging**:
   - Never print or console.log `GEMINI_API_KEY`, `CLOUDINARY_API_KEY`, or `CLOUDINARY_API_SECRET`.
   - Never pass API keys in query parameters or client responses.
3. **Strict Validation**:
   - Uploaded files are validated for supported MIME types (`image/jpeg`, `image/png`, `image/webp`) and size limits (5MB maximum) before reaching storage services.

---

## 9. Behavior When Configuration is Missing

| Scenario | Service | System Behavior | User / Client Impact |
|---|---|---|---|
| `GEMINI_API_KEY` missing / placeholder | Gemini AI | `geminiClient.isConfigured()` returns `false`; invokes deterministic rule-based classifier | Analysis completes successfully with heuristic classification; no crash |
| Gemini API error / rate limit / 400 | Gemini AI | Caught in `gemini.client.js` try-catch; returns `fallbackData` safely | Citizen receives valid analysis; system logs warning |
| Cloudinary keys missing / placeholder | Cloudinary | `storageService.isConfigured()` returns `false`; cleans up temp file and returns fallback URL | Intake succeeds; placeholder image metadata stored |
| Cloudinary upload network failure | Cloudinary | Cleans up local temp file; in production raises descriptive upload error, in test mode returns fallback | Clean HTTP 400/500 error response without leaking credentials |
